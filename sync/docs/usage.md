# Как запускать

Практическая шпаргалка: откуда и как запускать команды, что делает каждый параметр,
и что именно произойдёт при запуске — без технических деталей реализации.
Обновляется по мере того как появляются новые команды (см. `checklist.md` за прогрессом).

## Откуда и как

Все команды запускаются из директории `sync/`:

```
venv/bin/python main.py <команда> [параметры]
```

Перед запуском любой команды должен быть открыт Anki с установленным аддоном `anki_connect`
(проверить: `venv/bin/python main.py --help` покажет список команд, но сама команда упадёт
с ошибкой подключения, если Anki не запущен).

Список всех команд и их параметров: `venv/bin/python main.py --help`.
Параметры конкретной команды: `venv/bin/python main.py <команда> --help`.

## Общие параметры

Эти параметры повторяются в нескольких командах и означают одно и то же везде:

- `--deck` — какую колоду обрабатывать. Если не указать, берётся колода по умолчанию из
  настроек (`.env`, сейчас это `1_english::without_group::definition`). Любая из колод
  `definition`/`typing`/`word`/`typing_sentence` даёт один и тот же результат — это одни
  и те же карточки, просто показанные по-разному.
- `--dry-run` — ничего не менять, только показать, что было бы сделано. Всегда безопасно
  запускать несколько раз подряд.
- `--force` — переделать заново то, что обычно делается один раз и пропускается при
  повторных запусках. Нужен редко, обычный рабочий процесс его не использует.

## Команды

### `discover-new`

**Что делает:** ищет в Anki карточки, которые появились недавно (например, после того как
вы сами что-то доимпортировали в Anki) и ещё не были учтены этим инструментом. Ничего не
меняет — только показывает список: id карточки + слово.

**Параметры:** `--deck`

**Когда запускать:** просто чтобы посмотреть, что нового появилось, перед тем как запускать
`stamp`. Само по себе не обязательно — `stamp` и так найдёт эти карточки.

---

### `stamp`

**Что делает:** добавляет ко всем карточкам в выбранной колоде два служебных незаметных
поля — метку-идентификатор и отпечаток текущего содержимого — если у карточки их ещё нет.
Содержимое карточки (слово, определение, произношение, примеры и т.д.) не трогается вообще,
меняются только эти два служебных поля. Карточки, у которых метки уже стоят, второй раз не
трогаются — так что `stamp` можно свободно перезапускать когда угодно, он не наделает лишней
работы.

**Параметры:** `--deck`, `--dry-run`, `--force`

**Важно: `--force` для первого запуска не нужен.** Правило "не трогать поле, если оно уже
не пустое" само по себе пропускает уже помеченные карточки — именно поэтому `stamp` без
всяких флагов безопасно перезапускать сколько угодно раз. `--force` нужен только в обратном,
редком случае: переписать метку, которая **уже стоит**, — это не обычный рабочий процесс,
а осознанное действие "сбросить и проставить заново".

**Что произойдёт на практике:**
- `venv/bin/python main.py stamp` (без флагов), первый запуск на колоде: **реально** пометит
  **все** карточки в ней (меток ещё ни у кого нет) — запись в Anki произойдёт.
- Тот же запуск повторно, уже после того как карточки помечены (например, после того как вы
  доимпортировали новые слова в Anki): пометит только новые карточки, у старых ничего не
  изменится — это и есть "безопасно перезапускать".
- `venv/bin/python main.py stamp --dry-run` — то же самое, но без реальной записи, только план.
- `venv/bin/python main.py stamp --force` — не для обычного использования; переписал бы метки
  заново даже у уже помеченных карточек.

**Проверено на `1_english::without_group::definition`:** запущено пользователем по-настоящему
(без флагов) — все 1699 карточек помечены, повторная проверка показала 0 карточек без метки.

---

### `pull`

**Что делает:** скачивает карточки из выбранной колоды и сохраняет/обновляет их копию в своей
собственной базе данных (`data/sync.sqlite`) — по одной карточке за раз, а не всё сразу одним
блоком. Если с одной конкретной карточкой что-то не так (например, не удалось получить
данные), это не остановит весь процесс — эта карточка просто помечается как проблемная, а
остальные обрабатываются как обычно. На саму колоду в Anki `pull` не влияет никак — вообще
ничего там не меняет и не пишет, только считывает.

Перед тем как записать что-то в свою базу, `pull` по умолчанию показывает, что изменилось
(старое значение → новое), и спрашивает подтверждение на каждую карточку — если карточек
много, это означает много вопросов подряд. Это поведение можно отключить.

**Параметры:** `--deck`, `--skip-review`

- `--skip-review` — не спрашивать подтверждение на каждую карточку, применить все изменения
  сразу. Рекомендуется для больших колод и для самого первого запуска (когда все карточки новые
  и спрашивать не о чем — там просто нечего "путать").
- Без `--skip-review` — спросит подтверждение на каждую карточку, у которой есть что записать
  (новую или изменившуюся). Практично только для небольшого количества карточек за раз.
- `--dry-run` у `pull` **нет** — вместо предпросмотра здесь именно построчное подтверждение
  (см. выше) либо `--skip-review`, чтобы пропустить его.

**Что произойдёт на практике:**
- Первый запуск на колоде: каждая карточка — новая запись в базе данных ("created").
- Повторный запуск без изменений в Anki: ничего не меняется, каждая карточка отмечается как
  "без изменений" ("unchanged") — можно перезапускать сколько угодно раз без побочных эффектов.
- Если вы поправили что-то в самой карточке в Anki (например, определение) и потом запустили
  `pull` заново: увидите/примените именно это изменение — старое значение → новое.

**Проверено на `1_english::without_group::definition` (реальный запуск, `--skip-review`):**
все 1699 карточек сохранены в базу (`created=1699`), 0 ошибок. Повторный запуск сразу после:
`unchanged=1699, error=0` — подтверждено, что повторный `pull` без изменений в Anki ничего не
меняет.

### `match`, `confirm`, `review`, `enrich` — реализованы, но ещё не проверены на реальных данных

**Важно:** эти четыре команды написаны и покрыты автоматическими тестами (`venv/bin/pytest`),
но тесты используют вручную придуманные примеры, а не настоящий словарь Cambridge — потому что
в базе `data/sync.sqlite` пока нет ни одной настоящей словарной статьи (их должен туда записать
отдельный инструмент `lexicon-scraper`, который ещё не запускался на эту базу). Подробности —
в `docs/test-coverage.md`. Пока словаря нет, реально запускать эти команды не на чем — но когда
он появится, вот что каждая из них будет делать.

### `match`

**Что делает:** для уже скачанных (через `pull`) карточек ищет в словаре Cambridge подходящие
статьи по совпадению произношения (не по определению — определение вы могли отредактировать
вручную, а произношение меняется гораздо реже) и предлагает их как кандидатов на связывание.
Одному произношению может соответствовать несколько словарных значений — тогда предлагается
несколько кандидатов сразу, и это нормально. Ничего не пишет ни в Anki, ни поверх уже
подтверждённых связей — только предлагает варианты. Безопасно перезапускать когда угодно.

**Параметры:** `--deck`

### `confirm`

**Что делает:** подтверждает одного из предложенных `match`-ом кандидатов как окончательный —
именно он потом будет использоваться командой `enrich`. Либо конкретную пару карточка+статья
вручную, либо автоматически — но автоматически только там, где кандидат ровно один
(однозначный случай); если у карточки несколько кандидатов, `confirm --auto-single` их не
трогает, оставляя на ваше усмотрение.

**Параметры:** `--note ID --definition ID` (конкретная пара) **или** `--auto-single`
(автоматически, только однозначные случаи) — нужно указать что-то одно.

### `review`

**Что делает:** ничего не меняет, только показывает отчёт: какие карточки вообще не нашли
ни одного кандидата в словаре, у каких карточек несколько кандидатов и подтверждение ещё не
выбрано, и какие карточки застряли с ошибкой при последнем `pull`.

**Параметры:** нет (смотрит на все карточки сразу, а не на одну колоду).

### `enrich`

**Что делает:** дописывает в карточки Anki небольшой список полей, которые берутся из базы —
пока только уровень CEFR (насколько сложное слово). Пишет только туда, где это поле в Anki
сейчас пустое, и только если для карточки есть **подтверждённая** (не просто предложенная)
связь со словарной статьёй. Содержимое, которое вы сами заполняли (слово, определение и т.д.),
не трогает вообще.

**Параметры:** `--deck`, `--dry-run`, `--force`, `--skip-review` — работают так же, как у
`stamp`/`pull` (см. выше): `--dry-run` только показывает план, `--force` перезаписывает поле
даже если оно уже не пустое, `--skip-review` пропускает построчное подтверждение.

**Эта команда пишет в настоящую коллекцию Anki** — как и `stamp`, перед первым реальным
запуском стоит сначала посмотреть `--dry-run`.
